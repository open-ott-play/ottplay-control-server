Небольшой сервер для самостоятельного размещения, который доставляет удалённые команды проигрывателям OTT-play. Проигрыватели отправляют исходящие HTTP-запросы, поэтому телевизору не нужен открытый порт для входящих соединений. У каждого проигрывателя собственная очередь и токен доступа; для отправки команд используется отдельный токен администратора.

Дополнительный режим [надёжного управления](docs/reliable-control.md) предоставляет учётные данные интеграций с ограниченными правами, ограниченное долговременное хранение результатов команд, возобновляемое применение наборов Local/Home с точной проверкой настроек и явную передачу воспроизведения между прямым эфиром и архивом. Для этих возможностей нужны версии контроллера и CLI, содержащие это руководство. Точная проверка настроек и передача воспроизведения также требуют обновлённого проигрывателя. Указанная ниже более старая закреплённая версия установки этих возможностей не содержит. [Схема архитектуры](docs/assets/reliable-control.svg) показывает, где остаются настройки, учётные данные и состояние операций.

Сервер работает как один переносимый исполняемый файл Go с закреплённой версией DNS-библиотеки для необязательного обнаружения сервисов. Выпускаются пакеты для Linux amd64, arm64 и ARMv7; macOS Intel и Apple Silicon; Windows amd64 и arm64. Контейнерные образы поддерживают Linux amd64 и arm64. Для Kubernetes и k3s предусмотрен Helm-чарт.

## Запуск сервера

Скачайте подходящий архив со страницы [релизов](https://github.com/open-ott-play/ottplay-control-server/releases), проверьте его по манифесту релиза и распакуйте. В Windows используйте в командах ниже `ottplay-control-server.exe`.

```sh
./ottplay-control-server version
./ottplay-control-server init --config config.json --device-id living-room
./ottplay-control-server validate --config config.json
./ottplay-control-server serve --config config.json
```

Команда `init` создаёт случайные, разные учётные данные в новом файле, доступном в Unix только владельцу. Она отказывается перезаписывать существующий файл или символическую ссылку и никогда не выводит учётные данные. Храните файл закрытым; в Windows ограничьте его ACL учётной записью, от которой работает сервер. Файл `config.example.json` описывает поля и намеренно содержит недействительные токены-заглушки.

Адрес по умолчанию — `0.0.0.0:8081` (все интерфейсы IPv4, включая локальную сеть). Подключайте телевизоры по адресу сервера в локальной сети и его порту. Существующие конфигурации сохраняют явно заданное значение `listen`; замените его на `0.0.0.0:8081` или используйте `--listen 0.0.0.0:8081`, чтобы открыть доступ к установке, ранее доступной только через loopback. Добавьте **точный origin страницы** проигрывателя в `allowed_origins`, например `http://192.168.1.20:8443`. Схема, имя узла и порт должны совпадать; путь добавлять не нужно. Пустой список origin разрешает только небраузерные клиенты. Изменения конфигурации вступают в силу после перезапуска. Учётные данные устройства и администратора всё равно обязательны.

HTTP поддерживается для старых браузеров телевизоров в доверенной локальной сети. Если соединение проходит через недоверенную сеть, используйте HTTPS: `serve --config config.json --tls-cert server.crt --tls-key server.key` либо завершайте TLS на обратном прокси. Страницы проигрывателя, открытые по HTTPS, не могут подключаться к обычному HTTP-серверу в браузере. Нативные приложения также сохраняют транспортные ограничения операционной системы; эта настройка их не ослабляет.

Прямой HTTPS проверяет предоставленную цепочку сертификатов до открытия слушающего сокета: ключи RSA должны иметь длину не менее 2048 бит, ECDSA — не менее 224 бит; также поддерживается Ed25519. Перед обновлением замените сертификат с недостаточной длиной ключа. См. [политику TLS-сертификатов и область её действия](docs/security-design.md#direct-https-certificate-policy).

## Подключение проигрывателя

Используйте релиз проигрывателя с поддержкой подключения к серверу команд. Откройте **Настройки → Удалённое управление** и укажите:

1. **Адрес сервера:** IP-адрес или имя узла сервера, при необходимости с портом, либо полный адрес `http://` / `https://`. Для имени узла без схемы по умолчанию используется HTTP и порт 8081.
2. **Код доступа:** значение `token` записи этого проигрывателя в `devices`, ни в коем случае не `admin_token`.
3. **Подключить:** включите опрос и проверьте состояние в том же диалоге.

Проигрыватель сохраняет это подключение только в текущей установке и исключает его из резервных копий настроек и облачного переноса. Отдельный локальный HTTP-сервер не требуется. Веб-браузерам нужен разрешённый origin CORS; упакованные страницы телевизоров с `Origin: null` могут использовать явно заданную настройку `allow_null_origin` для предусмотренных маршрутов устройства и первоначального подключения. Это не открывает маршруты администратора или оператора диагностики.

## Пульт в терминале

[Иллюстрированное руководство по Android OTA](docs/android-ota.md) различает обычные обновления Capacitor по Wi-Fi (`ott DEVICE update --variant api22|full`, по умолчанию последняя бета; `--version` выбирает релиз) и отдельный агент с root-доступом. В нём описаны подписанные обновления агента и APK/helper, восстановление и проверка установленного результата.

[Руководство по Android ADB](docs/android-adb.md) описывает USB-доступ через рабочую станцию или Synology, управление экраном и клавиатурой, снимки экрана, журналы, установку APK и обычную перезагрузку, включая ограничения старых планшетов.

Необязательные [обнаружение и сопряжение DNS-SD](docs/discovery.md) позволяют проигрывателям найти контроллер через свой сетевой домен и получить индивидуальный токен устройства после `ott approve NAME CODE`. DNS содержит только метаданные сервиса. Существующие ручные подключения продолжают работать без включения обнаружения.

Python CLI предоставляет псевдонимы проигрывателей, текущее управление громкостью, поиск каналов, текущую EPG, выбор провайдера и настройку поддерживаемых провайдеров: [руководство CLI](docs/cli.md). И сервер, и проигрыватель должны поддерживать расширение запрос/ответ.

Python CLI устанавливается из рабочей копии исходников отдельно от архива нативного сервера. [Инструкции по установке и подключению](docs/cli.md#installation-and-connection) охватывают macOS/Linux и Windows, настройку Python/PATH и необходимые модули CLI. Они закрепляют проверенный коммит исходников разрабатываемой версии 0.1.1 с workbench и автономной проверкой; стабильный CLI v0.1.0 и архивы нативного сервера этих команд не содержат. [Обновляйте или откатывайте CLI](docs/cli.md#update-select-or-roll-back-the-cli), не заменяя существующую рабочую копию, средство запуска или закрытую конфигурацию. Локальные средства запуска могут использовать доступный только для чтения [обработчик плейлистов](docs/cli.md#local-playlist-resolver), чтобы искать каналы, текущие передачи и доступные для воспроизведения архивы без контроллера. После установки и настройки:

```sh
ott --help                 # all CLI command families
ott devices                # controller registrations and last contact
ott a1                     # this player's status and available controls
ott a1 prev                # previous channel in the active category (previous also works)
ott a1 next                # next channel, wrapping at the end of the category
ott a1 channels "РЕН"       # list channel-name matches without playing
ott a1 "РЕН ТВ HD"          # search and play a matching channel
ott a1 volume 35            # vol/v are equivalent command aliases
ott a1 aspect               # current Fit/Fill mode and saved-setting readback
ott a1 aspect fill          # fill the screen proportionally, cropping the edges
ott a1 aspect "Fit to screen" # full mode name; preserve the whole picture
ott a1 restart             # reload the player
ott a1 restart stream      # restart only the current stream
ott a1 standby             # stop playback and enter player standby; stay connected
ott a1 go                  # leave standby and start configured playback (start/wake also work)
ott a1 screenshot          # save a PNG; browser builds need a selected capture source
ott a1 shot -o screen.png  # short alias; never overwrites an existing file
ott a1 test run media-progress --report ./a1-progress
ott report verify ./a1-progress --json  # re-evaluate saved evidence offline
```

`a1` — пример псевдонима зарегистрированного проигрывателя, а не имя компьютера. См. [регистрацию и сопряжение](docs/cli.md#register-and-connect-a-player), [все команды с примерами](docs/cli.md#commands), [отключение и отзыв доступа](docs/cli.md#disconnect-deregister-or-revoke-a-player) и [устранение неполадок](docs/cli.md#troubleshooting).

Для постоянно включённого проигрывателя используйте [standby и go](docs/cli.md#stop-playback-while-keeping-the-player-online), чтобы остановить воспроизведение и позже возобновить его, не выходя из приложения. `stop` остаётся псевдонимом `standby`; `start` и `wake` — псевдонимами `go`. Удалённое управление должно оставаться подключённым, поэтому режим ожидания не означает полного отсутствия сетевого трафика устройства. `ott a1` показывает операции, заявленные проигрывателем. Принятая команда не подтверждает завершение выключения или запуска воспроизведения.

[Команды соотношения сторон](docs/cli.md#aspect-ratio-fit-and-fill) требуют обновлённых CLI, контроллера и проигрывателя, заявляющего возможность `aspect`. Изменение применяется после подтверждения; снова прочитайте `aspect`, чтобы проверить режим и сохранён ли он. Fill пропорционально обрезает края, а не растягивает изображение.

Удалённые [снимки экрана](docs/cli.md#remote-screenshots) требуют обновлённых CLI, контроллера и проигрывателя с поддерживаемым адаптером захвата. Включение подключения «Удалённое управление» разрешает этому контроллеру снимки экрана и диагностику; для нативных снимков отдельный переключатель разрешения не нужен. Браузерам по-прежнему требуется локальный выбор источника. Снимки могут содержать настройки проигрывателя, экраны PIN-кода и видимые учётные данные, поэтому подключайтесь только к доверенному контроллеру. `ott a1` сообщает о доступности и необходимости выбрать источник. Снимки экрана отделены от сбора структурированной телеметрии.

Чтобы перемешать все видео VPortal, соответствующие названию, и воспроизводить их по кругу:

```sh
ott l vpr "wedding"
```

`vpr` один раз перемешивает всю выборку, затем повторяет эту очередь. Для нового перемешивания запустите команду ещё раз. `vp` воспроизводит совпадения в порядке каталога; `vp --list` показывает их список, не меняя воспроизведение. См. [команды VPortal](docs/cli.md#commands).

Для явно заданной последовательности Plex с использованием сохранённой конфигурации Plex проигрывателя:

```sh
ott l plex preview 78777 78776 78775  # check availability without starting playback
ott l plex play 78777 78776 78775     # starts the first item from zero, in this order
ott l plex queue                     # current item and preparation/playback state
ott l plex next                      # advance once; no wrap at the last item
ott l plex stop                      # stop and clear this queue
ott l plex libraries                 # list libraries (requires plex_library support)
ott l plex shuffle "Tom and Jerry"   # shuffle one complete library, up to 500 items
ott l plex library --preview id:16    # read-only check of an explicit library
```

По умолчанию CLI ждёт до 45 секунд. Запись `ott -t 45 l plex shuffle "Tom and Jerry"` явно задаёт тот же тайм-аут ответа; она не ограничивает продолжительность воспроизведения видео. Сбор больших библиотек Plex может занять больше короткого тайм-аута в 10–15 секунд. Ставьте `-t SECONDS` (или `--timeout SECONDS`) перед псевдонимом проигрывателя. В разделе [тайм-аутов библиотек Plex](docs/cli.md#plex-libraries-by-name) приведены примеры предварительной проверки и действия при истечении тайм-аута запроса воспроизведения.

Очереди Plex требуют CLI, контроллер и проигрыватель с поддержкой `plex_queue`. `plex play --shuffle ID...` один раз перемешивает переданные ID. Очередь останавливается после последнего элемента, если действующая политика киоска не повторяет её. Пока очередь существует, обычные `next` и `prev` работают с ней; `plex stop` очищает её. Предварительная проверка никогда не переключает провайдера и не заменяет текущее воспроизведение. Ограничения и готовность описаны в [командах очередей Plex](docs/cli.md#ordered-plex-queues). Поиск библиотек дополнительно требует обновлённых проигрывателя и контроллера, заявляющих `plex_library`; он использует сохранённое подключение Plex проигрывателя и отклоняет неоднозначные или неполные выборки. См. [библиотеки Plex по имени](docs/cli.md#plex-libraries-by-name).

### Сохранение профилей локальных видео

С актуальными проигрывателем и контроллером локальные файлы и папки используют провайдера `offline`:

```sh
ott d1 provider offline
ott d1 profile save 1 "Family movies"
ott d1 profile export 1 family-movies.json
ott d1 profile import 2 family-movies.json
ott d1 profile load 2
```

Сначала подключите файлы или папки на проигрывателе. Сохранение записывает их конфигурацию и выбранное видео, не начиная воспроизведение. Экспорт переносит только описания; сами медиафайлы и разрешения ОС/браузера остаются на устройстве. На другой установке потребуется локальная привязка, а загрузка не означает подтверждённого воспроизведения. Настройка, возможности, ограничения переносимого формата и устранение неполадок описаны в [профилях локальных видео](docs/cli.md#local-videos-profiles).

### Сохранение текущего элемента между профилями

```sh
ott l fav add "Evening cartoons"    # capture this player's current item and profile
ott l fav                           # list saved entries and their stable IDs
ott l fav play "Evening cartoons"  # load that profile, then resolve and play the item
ott l fav rm fav-abc123              # use the actual ID from the list
```

Избранное сохраняется на целевом проигрывателе при обычных перезапусках. Выбор записи загружает сохранённого провайдера/профиль и получает свежую ссылку; изменённый источник или отсутствующий элемент приводят к ошибке без подмены другим каналом или фильмом. CLI, контроллер и проигрыватель должны поддерживать `favorites`; `ott l` показывает доступные операции. См. [избранное между профилями](docs/cli.md#favorites-across-profiles): псевдонимы, ограничения, смысл подтверждения и устранение неполадок.

### Загрузка сохранённого набора настроек

Храните именованные наборы в закрытом разделе `presets` файла `~/.config/ottplay-control/cli.json`. Каждый набор содержит пронумерованные профили M3U (плейлист и глубину архива в часах), учётные данные Plex и профиль M3U, который нужно выбрать после завершения загрузки. См. [пример конфигурации](docs/cli.md#named-setups).

```sh
ott presets                  # List saved setup names without credentials
ott t1 load local            # Configure a Mac player
ott o1 load local            # Configure a local OTT Server instance
ott l load home              # Configure the living-room TV
ott iphone load home        # Configure the iPhone
ott t1 profile 2             # Select the second saved M3U profile later
ott t1 provider plex         # Open the configured Plex provider later
```

CLI сначала проверяет весь набор, затем ждёт подтверждения проигрывателя перед отправкой каждого следующего изменения. Он обрабатывает загрузку провайдера, сохраняет Plex и слоты M3U и выбирает настроенный профиль M3U. Ошибка останавливает последовательность и сообщает подтверждённые шаги; запись с неопределённым результатом никогда не повторяется автоматически. Дополнительный сервис профилей или перезапуск контроллера не нужны. Храните эту конфигурацию закрытой: она содержит учётные данные провайдеров.

## Отправка команды

Этот пример читает токен администратора из локальной закрытой конфигурации, не помещая его в URL или аргументы командной строки:

```python
import json
import urllib.request

with open("config.json", encoding="utf-8") as stream:
    config = json.load(stream)
request = urllib.request.Request(
    "http://127.0.0.1:8081/api/webhook/commands?device_id=living-room",
    data=json.dumps({"command": "set_volume", "volume": 35}).encode(),
    headers={
        "Authorization": "Bearer " + config["admin_token"],
        "Content-Type": "application/json",
    },
)
with urllib.request.urlopen(request, timeout=5) as response:
    print(response.status)
```

Другие команды выбирают канал по номеру или названию, выбирают случайный канал, переключают провайдеров, показывают сообщение, изменяют плейлист M3U при наличии поддержки или завершают работу проигрывателя. Доступность зависит от платформы проигрывателя и текущего провайдера. См. [контракт API](docs/api.md).

В проигрывателе с поддержкой отдельного провайдера VPortal команда `ott a1 provider
vportal` выбирает его собственные 15 профилей. Используйте `profile N vportal LINK`, `profile N
name NAME` или закрытый файл `profile-config N FILE`, содержащий `name` и `vportal`, затем выбирайте настроенный слот командой `profile N`. Существующие профили M3U остаются отдельными. `profiles` показывает метаданные, не раскрывая ссылки кабинета или ключи.

После запуска фильма или очереди эпизодов VPortal команда `ott a1 kiosk on` блокирует этот выбор. Проигрыватель сохраняет очередь и позицию при перезагрузках и заново получает URL медиа для восстановления. Используйте `kiosk off`, чтобы выбрать другое название или изменить профили, затем `kiosk on`, чтобы зафиксировать выбор. Подтверждение киоска показывает название и количество эпизодов; запросы провайдера и URL потоков остаются на проигрывателе.

Для просмотра детьми используйте `ott a1 kiosk on --strict`: локальное касание показывает нижнюю панель видео. Обновлённые проигрыватели на основе core позволяют касаться шкалы времени или перетаскивать её для перемотки текущего эпизода VPortal/Plex; остальные локальные элементы управления остаются заблокированными. Старые проигрыватели, канальные киоски и оболочки, перехватывающие жесты шкалы времени, сохраняют панель только для чтения. Уже установленная блокировка сохраняет свою цель. Снимайте её с контроллера командой `ott a1 kiosk off`. Для веб-сайтов Android защита от выхода через систему требует отдельного закрепления приложения с PIN-кодом; см. [режим киоска](docs/cli.md#kiosk-mode).

## Удалённая диагностика

Начните с [быстрого старта workbench только для чтения](docs/workbench.md#quick-start): `doctor`, `inspect` интерфейса/медиа, поиск подтверждений операций, пакеты свидетельств, `health`, веб-/нативный `media-progress` и автономный `report verify`. Используются существующая конфигурация CLI администратора и псевдонимы проигрывателей. Нативное направление предназначено для отдельно установленного агента обслуживания Android; проигрыватели Tauri используют веб-проверку. Отчёты различают продвижение декодера и физическую проверку экрана/звука. См. [устранение неполадок workbench](docs/workbench.md#troubleshooting) при отсутствии возможностей, недоступных направлениях и неполных свидетельствах.

Необязательная [диагностика протокола 2](docs/remote-diagnostics.md) предоставляет явно включаемые сеансы для каждой среды выполнения с отдельными ограниченными учётными данными оператора и ограниченной структурированной телеметрией. Включённое подключение проигрывателя даёт локальное разрешение без дополнительного запроса доверия; срок действия сеанса каждого захвата всё равно ограничен. Опрос управления диагностикой не зависит от существующей очереди команд.

[Руководство по диагностическому CLI и MCP](docs/diagnostics-cli.md) описывает установку, учётные данные оператора, настройку подключения, каждую диагностическую команду и инструмент, примеры захвата и исправления, отзыв доступа среды выполнения и устранение неполадок. `ott diagnostics --help` показывает это отдельное семейство команд; обычные псевдонимы проигрывателей и учётные данные администратора не дают доступа к диагностике.

Очереди ограничены, по умолчанию истекают через 60 секунд и хранятся в памяти. Перезапуск сервера удаляет ожидающие команды. Запускайте одну реплику; независимые реплики не делятся очередями. Проигрыватель подтверждает попытку доставки, а не фактическое воспроизведение или аппаратную громкость. Повторы сетевых запросов дедуплицируются в рамках работающего сеанса проигрывателя, но не между перезапусками приложения.

Сервер следует API команд необязательного примера `local_proxy.py` из [OTT-play FOSS](https://github.com/open-ott-play/ottplay-foss), с отдельными учётными данными администратора/устройства и подтверждаемой доставкой. Старый прокси остаётся самостоятельным компонентом. Этот проект не проксирует медиа и не меняет сетевую работу HLS, EPG или провайдеров проигрывателя.
