# Сервер управления OTT-play

[English](README.md) · [Русский](README.ru.md) · [Документация / Wiki](docs/wiki/Home.ru.md)

Небольшой самостоятельный сервер доставляет команды плеерам OTT-play. Плеер
сам обращается к серверу по HTTP: телевизору не нужен открытый входящий порт.
У каждого устройства отдельные очередь и токен. Администратор управляет всеми
устройствами; необязательные операторы ограничены списком устройств и действий.

Сервер — один исполняемый файл Go. Пакеты выпускаются для Linux amd64/arm64/ARMv7,
macOS Intel/Apple Silicon и Windows amd64/arm64. Контейнеры поддерживают Linux
amd64/arm64, для Kubernetes/k3s есть Helm chart. Полный справочник параметров,
платформ и старых команд находится в [английском README](README.md).

- [Android: строгий киоск Plex и автозапуск](docs/android-kiosk-setup.ru.md)

## Запуск

Скачайте подходящий архив из [Releases](https://github.com/open-ott-play/ottplay-control-server/releases),
проверьте его по манифесту и распакуйте. В Windows используйте имя
`ottplay-control-server.exe`:

```sh
./ottplay-control-server version
./ottplay-control-server init --config config.json --device-id living-room
./ottplay-control-server validate --config config.json
./ottplay-control-server serve --config config.json
```

`init` создаёт разные случайные токены и отказывается заменять существующий
файл. Храните конфигурацию приватно: права 0600 в Unix, ограниченный ACL в
Windows. Пример `config.example.json` содержит непригодные для работы заглушки.

По умолчанию сервер слушает `0.0.0.0:8081`. В `allowed_origins` добавьте точный
origin страницы плеера: протокол, имя и порт без пути. Пустой список допускает
только клиентов без браузерного Origin. Для старых упакованных ТВ-страниц
существует отдельный параметр `allow_null_origin`; он не открывает
административные и диагностические маршруты.

В доверенной локальной сети поддерживается HTTP. Для недоверенной сети
используйте HTTPS, встроенный TLS или обратный прокси. Браузерная HTTPS-страница
не может обращаться к обычному HTTP-серверу. HTTPS проверяет цепочку сертификатов
и минимальную стойкость ключей; [подробности](docs/security-design.md).

## Подключение плеера

В **Настройки → Удалённое управление** задайте адрес сервера и токен устройства
из `devices`, затем включите подключение. Не вводите `admin_token` в телевизор.
Соединение сохраняется на текущем устройстве и не входит в резервные копии
настроек. Опциональные [DNS-SD и сопряжение](docs/discovery.md) помогают найти
контроллер и выдать отдельный токен через `ott approve NAME CODE`.

## CLI и надёжные операции

CLI устанавливается отдельно из исходников и требует Python 3.12 или новее.
Сохраняйте все `cli/*.py` одной версии рядом, включая `preset_session.py`.
Нативный архив сервера не включает Python CLI. [Полная установка](docs/cli.md)
содержит исторически проверенный commit; новые операции ниже требуют более
новой версии, содержащей [руководство надёжного управления](docs/reliable-control.ru.md),
а также соответствующих контроллера и плеера.

```sh
ott devices
ott tv
ott tv next
ott tv volume 35
ott tv screenshot
ott tv load Local plan
ott tv load Local apply
ott tv load Local resume
ott tv load Local verify
ott handoff living-room bedroom
```

![Архитектура надёжного управления](docs/assets/reliable-control.svg)

Новые возможности:

- Операторы команд для HA/RF/агентов с точными разрешениями, независимыми от
  токенов плееров и доступа к диагностике.
- Необязательный приватный журнал исходов. Неопределённая команда после
  перезапуска не воспроизводится автоматически; размеры и сроки ограничены.
- Контрольные точки Local/Home и точная проверка настроек без выдачи их
  секретных значений. Старый `load PRESET` сохранён.
- Явный перенос эфира/архива между плеерами с одинаковым настроенным источником.
  Целевой плеер самостоятельно получает URL; исходный продолжает воспроизведение.

Журнал не превращает сервер в постоянную очередь и не гарантирует однократное
выполнение. Применение профиля не является общей транзакцией нескольких
устройств. Перенос VOD, разные аккаунты и постоянная синхронизация истории
не входят в первую версию. Успешный ответ плеера не доказывает физический звук
или изображение — это проверяется отдельно.

## Разработка, диагностика и выпуски

Для USB-планшетов доступен [общий Android manager](docs/android-usb-manager.ru.md):
один контейнер ADB, сохранённые ключи и отдельное состояние восстановления
каждого устройства. Неизвестные идентификаторы и одинаковые серийные номера
блокируются. Обычное выключение экрана не запускает автоматическое пробуждение.

```sh
go vet ./...
go test -race ./...
python3 -m unittest discover -s tests
```
