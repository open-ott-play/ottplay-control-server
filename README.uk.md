Невеликий сервер для самостійного розміщення, який доставляє віддалені команди програвачам OTT-play. Програвачі надсилають вихідні HTTP-запити, тому телевізору не потрібен відкритий порт для вхідних з'єднань. Кожен програвач має власну чергу й токен доступу; команди надсилаються окремим токеном адміністратора.

Додаткове [надійне керування](docs/reliable-control.md) надає облікові дані інтеграцій з обмеженими правами, обмежене довготривале зберігання результатів команд, відновлюване застосування конфігурацій Local/Home з точною перевіркою налаштувань та явне передавання між прямим ефіром і архівним відтворенням. Ці можливості потребують ревізій контролера й CLI, які містять цей посібник. Точна перевірка та передавання також потребують оновленого програвача. Зазначена нижче старіша закріплена ревізія встановлення цих функцій не містить. [Схема архітектури](docs/assets/reliable-control.svg) показує, де залишаються налаштування, облікові дані та стан операцій.

Сервер працює як один переносний виконуваний файл Go із закріпленою версією бібліотеки DNS для необов'язкового виявлення служб. Пакети випускаються для Linux amd64, arm64 і ARMv7; macOS Intel та Apple Silicon; Windows amd64 і arm64. Контейнерні образи підтримують Linux amd64 і arm64. Kubernetes та k3s використовують включений Helm chart.

## Запуск сервера

Завантажте відповідний архів із [випусків](https://github.com/open-ott-play/ottplay-control-server/releases), перевірте його за маніфестом випуску й розпакуйте. У Windows використовуйте `ottplay-control-server.exe` в наведених командах.

```sh
./ottplay-control-server version
./ottplay-control-server init --config config.json --device-id living-room
./ottplay-control-server validate --config config.json
./ottplay-control-server serve --config config.json
```

`init` створює випадкові, різні облікові дані в новому файлі, доступному в Unix лише власнику. Команда відмовляється перезаписувати наявний файл або символічне посилання й ніколи не виводить облікові дані. Зберігайте файл приватним; у Windows обмежте його ACL обліковим записом, від якого працює сервер. `config.example.json` описує поля й навмисно містить недійсні токени-заповнювачі.

Типова адреса — `0.0.0.0:8081` (усі інтерфейси IPv4, включно з LAN). Підключайте телевізори через LAN-адресу й порт сервера. Наявні конфігурації зберігають явне значення `listen`; змініть його на `0.0.0.0:8081` або використайте `--listen 0.0.0.0:8081`, щоб відкрити доступ до встановлення, раніше обмеженого loopback. Додайте **точний origin сторінки** програвача до `allowed_origins`, наприклад `http://192.168.1.20:8443`. Схема, ім'я вузла й порт мають збігатися; не додавайте шлях. Порожній список origin дозволяє лише небраузерні клієнти. Зміни конфігурації набувають чинності після перезапуску. Облікові дані пристрою й адміністратора залишаються обов'язковими.

HTTP підтримується для старих браузерів телевізорів у довіреній LAN. Якщо з'єднання проходить через недовірену мережу, використовуйте HTTPS: `serve --config config.json --tls-cert server.crt --tls-key server.key`, або завершуйте TLS на зворотному проксі. Сторінки програвача, відкриті через HTTPS, не можуть у браузері підключатися до звичайного HTTP-сервера. Нативні застосунки також зберігають транспортні правила операційної системи; це налаштування їх не послаблює.

Прямий HTTPS перевіряє наданий ланцюжок сертифікатів перед відкриттям прослуховування: ключі RSA повинні мати щонайменше 2048 біт, ECDSA — щонайменше 224 біти; також підтримується Ed25519. Перед оновленням замініть сертифікат із надто коротким ключем. Дивіться [політику сертифікатів TLS та її сферу дії](docs/security-design.md#direct-https-certificate-policy).

## Підключення програвача

Використовуйте випуск програвача з підтримкою підключення до сервера команд. Відкрийте **Налаштування → Віддалене керування** та введіть:

1. **Адреса сервера:** IP або ім'я вузла, за потреби з портом, чи повна адреса `http://` / `https://`. Для вузла без схеми типово використовується HTTP на порту 8081.
2. **Код доступу:** `token` запису цього програвача в `devices`, ніколи не `admin_token`.
3. **Підключити:** увімкніть опитування й перевірте стан у тому самому діалозі.

Програвач зберігає це підключення лише в поточному встановленні та виключає його з резервних копій налаштувань і хмарного перенесення. Окремий локальний HTTP-сервер не потрібен. Веббраузери потребують дозволеного origin CORS; упаковані сторінки телевізорів з `Origin: null` можуть використовувати явне налаштування `allow_null_origin` для передбачених маршрутів пристрою й початкового підключення. Це не відкриває маршрути адміністратора чи оператора діагностики.

## Пульт у терміналі

[Ілюстрований посібник Android OTA](docs/android-ota.md) розрізняє звичайні оновлення Capacitor через Wi-Fi (`ott DEVICE update --variant api22|full`, типово остання бета; `--version` вибирає випуск) та окремий агент із root-доступом. Він пояснює підписані оновлення агента й APK/helper, відновлення та перевірку встановленого результату.

[Посібник Android ADB](docs/android-adb.md) охоплює USB-доступ через робочу станцію або Synology, керування екраном і клавіатурою, знімки екрана, журнали, встановлення APK та звичайне перезавантаження, включно з обмеженнями старих планшетів.

Необов'язкові [виявлення та сполучення DNS-SD](docs/discovery.md) дозволяють програвачам знаходити контролер через мережевий домен і отримувати індивідуальний токен пристрою після `ott approve NAME CODE`. DNS містить лише метадані служби. Наявні ручні підключення продовжують працювати без увімкнення виявлення.

Python CLI надає псевдоніми програвачів, поточне керування гучністю, пошук каналів, актуальну EPG, вибір провайдера та налаштування підтримуваних провайдерів: [посібник CLI](docs/cli.md). І сервер, і програвач повинні містити розширення запит/відповідь.

Python CLI встановлюється з робочої копії вихідного коду, окремо від архіву нативного сервера. [Кроки встановлення та налаштування](docs/cli.md#installation-and-connection) охоплюють macOS/Linux і Windows, налаштування Python/PATH та необхідні модулі CLI. Вони закріплюють перевірений коміт розробки 0.1.1 із workbench та автономною перевіркою; стабільний CLI v0.1.0 і архіви нативного сервера цих команд не містять. [Оновлюйте або відкочуйте CLI](docs/cli.md#update-select-or-roll-back-the-cli), не замінюючи наявну робочу копію, засіб запуску чи приватну конфігурацію. Локальні засоби запуску можуть використовувати [обробник плейлистів](docs/cli.md#local-playlist-resolver) лише для читання, щоб шукати канали, поточні передачі й придатні до відтворення архіви без контролера. Після встановлення й налаштування:

```sh
ott --help                 # all CLI command families
ott devices                # controller registrations and last contact
ott a1                     # this player's status and available controls
ott a1 prev                # previous channel in the active category (previous also works)
ott a1 next                # next channel, wrapping at the end of the category
ott a1 channels "РЕН"       # list channel-name matches without playing
ott a1 "РЕН ТВ HD"          # search and play a matching channel
ott a1 volume 35            # vol/v are equivalent command aliases
ott a1 aspect               # current Fit/Fill mode and saved-setting readback
ott a1 aspect fill          # fill the screen proportionally, cropping the edges
ott a1 aspect "Fit to screen" # full mode name; preserve the whole picture
ott a1 restart             # reload the player
ott a1 restart stream      # restart only the current stream
ott a1 standby             # stop playback and enter player standby; stay connected
ott a1 go                  # leave standby and start configured playback (start/wake also work)
ott a1 screenshot          # save a PNG; browser builds need a selected capture source
ott a1 shot -o screen.png  # short alias; never overwrites an existing file
ott a1 test run media-progress --report ./a1-progress
ott report verify ./a1-progress --json  # re-evaluate saved evidence offline
```

`a1` — приклад псевдоніма зареєстрованого програвача, а не ім'я комп'ютера. Дивіться [реєстрацію та сполучення](docs/cli.md#register-and-connect-a-player), [усі команди з прикладами](docs/cli.md#commands), [відключення та відкликання доступу](docs/cli.md#disconnect-deregister-or-revoke-a-player) і [усунення несправностей](docs/cli.md#troubleshooting).

Для постійно ввімкненого програвача використовуйте [standby та go](docs/cli.md#stop-playback-while-keeping-the-player-online), щоб зупинити відтворення й пізніше відновити його без виходу із застосунку. `stop` залишається псевдонімом `standby`; `start` і `wake` — псевдонімами `go`. Віддалене керування має залишатися підключеним, тому режим очікування не гарантує відсутності мережевого трафіку. `ott a1` показує операції, заявлені програвачем. Прийнята команда не підтверджує завершення вимкнення чи запуску відтворення.

[Команди співвідношення сторін](docs/cli.md#aspect-ratio-fit-and-fill) потребують оновлених CLI, контролера та програвача, що заявляє можливість `aspect`. Зміна застосовується після підтвердження; зчитайте `aspect` знову, щоб перевірити режим і його збереження. Fill пропорційно обрізає краї, а не розтягує зображення.

Віддалені [знімки екрана](docs/cli.md#remote-screenshots) потребують оновлених CLI, контролера та програвача з підтримуваним адаптером захоплення. Увімкнення підключення «Віддалене керування» дозволяє цьому контролеру знімки екрана й діагностику; для нативних знімків окремий перемикач дозволу не потрібен. Браузери все одно потребують локального вибору джерела. Зображення можуть містити налаштування, екрани PIN і видимі облікові дані, тому підключайтеся лише до довіреного контролера. `ott a1` повідомляє про доступність і потрібний вибір джерела. Знімки екрана відокремлені від збирання структурованої телеметрії.

Щоб перемішати всі відео VPortal, які відповідають назві, та відтворювати їх циклічно:

```sh
ott l vpr "wedding"
```

`vpr` один раз перемішує всю вибірку, а потім повторює цю чергу. Запустіть його знову для нового перемішування. `vp` відтворює збіги в порядку каталогу; `vp --list` показує їх без зміни відтворення. Дивіться [команди VPortal](docs/cli.md#commands).

Для явно заданої послідовності Plex зі збереженою конфігурацією Plex програвача:

```sh
ott l plex preview 78777 78776 78775  # check availability without starting playback
ott l plex play 78777 78776 78775     # starts the first item from zero, in this order
ott l plex queue                     # current item and preparation/playback state
ott l plex next                      # advance once; no wrap at the last item
ott l plex stop                      # stop and clear this queue
ott l plex libraries                 # list libraries (requires plex_library support)
ott l plex shuffle "Tom and Jerry"   # shuffle one complete library, up to 500 items
ott l plex library --preview id:16    # read-only check of an explicit library
```

CLI типово очікує до 45 секунд. Запис `ott -t 45 l plex shuffle "Tom and Jerry"` явно задає той самий час очікування відповіді; він не обмежує тривалість відтворення відео. Збирання великих бібліотек Plex може тривати довше за короткий тайм-аут 10–15 секунд. Розміщуйте `-t SECONDS` (або `--timeout SECONDS`) перед псевдонімом програвача. Приклади попередньої перевірки та дії при завершенні часу запиту відтворення наведено в [тайм-аутах бібліотек Plex](docs/cli.md#plex-libraries-by-name).

Черги Plex потребують CLI, контролера та програвача з реалізацією `plex_queue`. `plex play --shuffle ID...` один раз перемішує передані ID. Черги зупиняються після останнього елемента, якщо їх не повторює наявна політика кіоску. Поки черга існує, звичайні `next` і `prev` працюють із нею; `plex stop` очищує її. Попередня перевірка ніколи не перемикає провайдера й не замінює поточне відтворення. Обмеження та готовність описано в [командах черг Plex](docs/cli.md#ordered-plex-queues). Пошук бібліотек додатково потребує оновлених програвача й контролера, що заявляють `plex_library`; він використовує збережене підключення Plex програвача та відхиляє неоднозначні або неповні вибірки. Дивіться [бібліотеки Plex за назвою](docs/cli.md#plex-libraries-by-name).

### Збереження профілів локальних відео

З актуальними програвачем і контролером локальні файли/теки використовують провайдера `offline`:

```sh
ott d1 provider offline
ott d1 profile save 1 "Family movies"
ott d1 profile export 1 family-movies.json
ott d1 profile import 2 family-movies.json
ott d1 profile load 2
```

Спочатку підключіть файли/теки на програвачі. Збереження записує їхню конфігурацію та вибране відео без запуску відтворення. Експорт переносить лише описи; медіа та дозволи ОС/браузера залишаються на пристрої. Інше встановлення потребує локального прив'язування, а завантаження не означає підтвердженого відтворення. Налаштування, можливості, обмеження переносного формату й усунення несправностей описано в [профілях локальних відео](docs/cli.md#local-videos-profiles).

### Збереження поточного елемента між профілями

```sh
ott l fav add "Evening cartoons"    # capture this player's current item and profile
ott l fav                           # list saved entries and their stable IDs
ott l fav play "Evening cartoons"  # load that profile, then resolve and play the item
ott l fav rm fav-abc123              # use the actual ID from the list
```

Обране зберігається на цільовому програвачі після звичайних перезапусків. Вибір запису завантажує збереженого провайдера/профіль і отримує свіже посилання; змінене джерело або відсутній елемент спричиняє помилку без підміни іншим каналом чи фільмом. CLI, контролер і програвач повинні підтримувати `favorites`; `ott l` показує доступні операції. Дивіться [обране між профілями](docs/cli.md#favorites-across-profiles): псевдоніми, обмеження, зміст підтвердження й усунення несправностей.

### Завантаження збереженої конфігурації

Зберігайте іменовані конфігурації в приватному розділі `presets` файлу `~/.config/ottplay-control/cli.json`. Кожна містить нумеровані профілі M3U (плейлист і години архіву), облікові дані Plex та профіль M3U для вибору після завершення завантаження. Дивіться [приклад конфігурації](docs/cli.md#named-setups).

```sh
ott presets                  # List saved setup names without credentials
ott t1 load local            # Configure a Mac player
ott o1 load local            # Configure a local OTT Server instance
ott l load home              # Configure the living-room TV
ott iphone load home        # Configure the iPhone
ott t1 profile 2             # Select the second saved M3U profile later
ott t1 provider plex         # Open the configured Plex provider later
```

CLI спочатку перевіряє всю конфігурацію, потім очікує підтвердження програвача перед надсиланням кожної наступної зміни. Він обробляє завантаження провайдера, зберігає Plex і слоти M3U та вибирає налаштований профіль M3U. Помилка зупиняє послідовність і повідомляє підтверджені кроки; запис із невизначеним результатом ніколи не повторюється автоматично. Додаткова служба профілів чи перезапуск контролера не потрібні. Зберігайте цю конфігурацію приватною: вона містить облікові дані провайдерів.

## Надсилання команди

Цей приклад читає токен адміністратора з локальної приватної конфігурації, не розміщуючи його в URL або аргументах командного рядка:

```python
import json
import urllib.request

with open("config.json", encoding="utf-8") as stream:
    config = json.load(stream)
request = urllib.request.Request(
    "http://127.0.0.1:8081/api/webhook/commands?device_id=living-room",
    data=json.dumps({"command": "set_volume", "volume": 35}).encode(),
    headers={
        "Authorization": "Bearer " + config["admin_token"],
        "Content-Type": "application/json",
    },
)
with urllib.request.urlopen(request, timeout=5) as response:
    print(response.status)
```

Інші команди вибирають канал за номером чи назвою, випадковий канал, перемикають провайдерів, показують повідомлення, змінюють плейлист M3U за наявності підтримки або завершують роботу програвача. Доступність залежить від платформи програвача й поточного провайдера. Дивіться [контракт API](docs/api.md).

У програвачі з підтримкою окремого провайдера VPortal команда `ott a1 provider
vportal` вибирає його власні 15 профілів. Використовуйте `profile N vportal LINK`, `profile N
name NAME` або приватний файл `profile-config N FILE` із `name` та `vportal`, потім вибирайте налаштований слот через `profile N`. Наявні профілі M3U залишаються окремими. `profiles` повідомляє метадані, не розкриваючи посилання кабінету або ключі.

Після запуску фільму чи черги епізодів VPortal команда `ott a1 kiosk on` блокує цей вибір. Програвач зберігає чергу та її позицію після перезавантажень сторінки й знову отримує URL медіа для відновлення. Використовуйте `kiosk off`, щоб вибрати іншу назву чи змінити профілі, потім `kiosk on`, щоб заблокувати. Підтвердження кіоску показує назву й кількість епізодів; запити провайдера та URL потоків залишаються на програвачі.

Для відтворення дітям використовуйте `ott a1 kiosk on --strict`: локальне торкання показує нижню панель відео. Оновлені програвачі core дозволяють торкатися або перетягувати часову шкалу для перемотування поточного епізоду VPortal/Plex; інші локальні елементи керування залишаються заблокованими. Старі програвачі, канальні кіоски й оболонки, що перехоплюють жести часової шкали, зберігають панель лише для читання. Наявне блокування зберігає свою ціль. Знімайте його з контролера через `ott a1 kiosk off`. На вебсайтах Android захист від системного виходу потребує окремого закріплення застосунку з PIN; дивіться [режим кіоску](docs/cli.md#kiosk-mode).

## Віддалена діагностика

Почніть із [швидкого старту workbench лише для читання](docs/workbench.md#quick-start) для `doctor`, `inspect` інтерфейсу/медіа, пошуку підтверджень операцій, пакетів доказів, `health`, веб-/нативного `media-progress` та автономного `report verify`. Використовуються наявна конфігурація CLI адміністратора й псевдоніми програвачів. Нативний напрям призначений для окремо підготовленого агента обслуговування Android; програвачі Tauri використовують вебінспекцію. Звіти розрізняють поступ декодера й фізичну перевірку екрана/звуку. Дивіться [усунення несправностей workbench](docs/workbench.md#troubleshooting) при відсутніх можливостях, недоступних напрямах і неповних доказах.

Необов'язкова [діагностика протоколу 2](docs/remote-diagnostics.md) надає явно ввімкнені сеанси для кожного середовища виконання з окремими обмеженими обліковими даними оператора та обмеженою структурованою телеметрією. Увімкнене підключення програвача забезпечує локальний дозвіл без додаткового запиту довіри; кожне захоплення все одно має обмежений термін сеансу. Опитування керування діагностикою незалежне від наявної черги команд.

[Посібник діагностичного CLI та MCP](docs/diagnostics-cli.md) охоплює встановлення, облікові дані оператора, підключення, кожну діагностичну команду/інструмент, приклади захоплення й виправлення, відкликання доступу середовища виконання та усунення несправностей. `ott diagnostics --help` показує цю окрему родину команд; звичайні псевдоніми програвачів та облікові дані адміністратора не надають діагностичного доступу.

Черги обмежені, типово спливають через 60 секунд і зберігаються в пам'яті. Перезапуск сервера видаляє команди, що очікують. Запускайте одну репліку; незалежні репліки не діляться чергами. Програвач підтверджує спробу доставки, а не фактичне відтворення чи апаратну гучність. Повторні мережеві запити дедуплікуються в межах активного сеансу програвача, а не між перезапусками застосунку.

Сервер дотримується API команд необов'язкового прикладу `local_proxy.py` з [OTT-play FOSS](https://github.com/open-ott-play/ottplay-foss), з окремими обліковими даними адміністратора/пристрою та підтверджуваною доставкою. Старий проксі залишається окремим компонентом. Цей проєкт не проксіює медіа й не змінює мережеву роботу HLS, EPG або провайдерів програвача.
