# Обновление Capacitor по Wi-Fi

[English](android-ota.md) · [Полная справка CLI](cli.md#capacitor-apk-updates-over-wi-fi)

Плеер должен быть запущен, подключён к контроллеру и уже содержать нативный
плагин `AppUpdate`. Установите все файлы `cli/*.py` одной версии. Обновление
CLI само по себе не добавляет этот плагин в установленное приложение.

```sh
ott k8a
ott k8a update status
```

Первая команда показывает состояние и доступные команды. Примеры обновления
появляются только при объявленной поддержке `AppUpdate`. Обе команды лишь
читают состояние, не запускают загрузку или установку.

Выберите вариант APK по версии Android. Следующие команды загружают и
проверяют APK, но не вызывают установщик; используйте только подходящую:

```sh
ott k8a update --variant api22 --prepare-only  # Android 5.1/6
ott tablet update --variant full --prepare-only  # Android 7+
```

Без `--version` выбирается наибольший номер опубликованной beta среди
100 релизов, возвращённых GitHub, независимо от порядка списка.
`--version v1.1.58-beta.11` фиксирует конкретный опубликованный релиз.
Перед обслуживанием проверьте режим киоска и при необходимости явно отключите
его и разблокируйте защищённые настройки. CLI не меняет эти ограничения сам.

Для установки подготовленного APK используйте его точный SHA-256 из
`update status`, заменив `SHA256` ниже. Запрос отправляется один раз:

```sh
ott --receipt k8a update install SHA256
ott k8a update status
```

В квитанции `action: "app_update"` и `status: "ok"` означают успешный ответ
на запрос, а не завершение установки. При `awaiting_confirmation` подтвердите
системный диалог Android и снова откройте плеер; затем проверьте установленную
версию через `update status`. При потере ответа не повторяйте установку
вслепую. Автоматическая установка без подтверждения не обещается.

Слова `update`, `beta`, `status`, `prepare`, `install` принимаются в любом
регистре; адрес APK и хеш не изменяются. Команда `android update` относится
к отдельному заранее настроенному root-агенту, а не к этому механизму.
