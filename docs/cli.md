# Управление плеерами из терминала

`cli/ott.py` работает на Python 3 без дополнительных пакетов. Команда принимает
короткое имя плеера, затем действие. Каждому плееру назначьте отдельный device ID
(рекомендуется его Device UUID из настроек) и отдельный device token.
Один код нельзя использовать одновременно в нескольких плеерах: они будут
соревноваться за одну очередь.

## Установка и подключение

Ниже приведена установка для macOS/Linux, где CLI создаёт файлы с правами 600.
На Windows запускайте скрипт через `python cli/ott.py` и храните конфигурацию в
личном каталоге с закрытым доступом NTFS: POSIX-права 600 там не применяются,
доступ к новым файлам определяется ACL родительского каталога.

```sh
mkdir -p ~/.local/bin ~/.config/ottplay-control
ln -s /absolute/path/to/ottplay-control-server/cli/ott.py ~/.local/bin/ott
chmod 700 ~/.config/ottplay-control
```

Создайте `~/.config/ottplay-control/cli.json` (права 600):

```json
{
  "server": "http://127.0.0.1:8081",
  "player_server": "https://control.example.com",
  "server_config": "/absolute/path/to/private-server-config.json",
  "players": {"tv": "dev_your_tv_uuid", "mac": "dev_your_mac_uuid"}
}
```

`server_config` — приватный JSON сервера с `admin_token` и `devices`. Он не должен
попадать в репозиторий или публичные файлы сайта. `server` — адрес, доступный CLI;
`player_server` — адрес, который нужно вводить в плеерах. Можно использовать один
HTTPS-адрес для обоих. `OTT_CONFIG` или `--config FILE` выбирают другой профиль.

```sh
ott devices
ott add tv DEVICE_UUID
ott pair tv
```

`add` создаёт отдельный случайный токен, сохраняет его в server_config и привязывает
имя. Для обычной установки после этого перезапустите сервер. Для установленного
в k3s сервера можно добавить в cli.json объект `kubernetes` с полями `context`,
`namespace`, `secret`, `deployment`. Тогда `add` обновляет ключ `config.json`
указанного Secret и перезапускает Deployment. Он проверяет resourceVersion и
совпадение локальной/кластерной конфигурации, чтобы не затереть чужие изменения.
Перезапуск очищает все незавершённые очереди. `alias NAME UUID` привязывает имя к
уже зарегистрированному устройству без перезапуска.

Если Kubernetes-добавление оборвалось, повторите тот же `ott add NAME UUID`.
Приватный файл `cli.json.pending-add.json` сохраняет выданный код до изменения
Secret. CLI сверяет кластер с состоянием до/после операции, продолжает с тем же
кодом и удаляет этот файл только после успешного rollout. Посторонние изменения
конфигурации останавливают восстановление. Пока операция не завершена, не удаляйте
файл восстановления и не добавляйте другое устройство. Повторный restart очищает
незавершённые очереди; подключение плеера выполняйте после успешного `add`.
Изменения других псевдонимов и полей `cli.json` во время операции сохраняются.
Изменение целевого псевдонима, адреса сервера или Kubernetes/server_config требует
сверки; журнал остаётся на месте, даже если rollout уже завершился.

`pair` показывает device token, **не admin_token**. В плеере откройте
**Настройки → Удалённое управление → Сервер команд**. Введите показанные адрес и
код доступа, нажмите **Подключить**, дождитесь «Connected». Это отдельная настройка
для каждого браузерного origin, телевизора и Tauri-инстанса. Для новых браузерных
адресов добавьте точный origin в `allowed_origins` и перезапустите сервер.

HTTPS-страницы (включая here.now) требуют HTTPS-сервер. Tauri использует нативный
HTTP-мост; TV-браузер делает исходящие XHR-запросы и не требует входящего порта на
телевизоре. Для пакетных TV-приложений с Origin `null` предусмотрен отдельный
`allow_null_origin: true`, действующий только на device API. Центральный сервер
плеера на 8443–8446 не является сервером команд.

## Команды

```sh
ott tv                      # UUID, провайдер, готовность, число каналов, громкость
ott tv 12                   # номер канала из s, начиная с 1
ott tv первый               # точное имя, иначе подстрока
ott tv play s               # канал с именем s, совпадающим с командой
ott tv s                    # все каналы текущего провайдера
ott tv s HD                 # фильтр по названию канала
ott tv p                    # канал — текущая программа
ott tv p новости            # фильтр по названию текущей программы
ott tv v                    # текущая громкость, 0–100%
ott tv v 35                 # абсолютное значение
ott tv v +5                 # относительное изменение на устройстве
ott tv v -5
ott tv providers            # провайдеры, активный отмечен *, индексы с 0
ott tv provider xtream      # ID, индекс или фрагмент названия
ott tv provider-config ~/private/xtream.json
ott tv playlist https://example.com/list.m3u
ott tv random               # случайный канал из текущего списка воспроизведения
ott tv random 1 10
ott tv msg Привет
ott tv exit                 # закрытие / standby, зависит от платформы
ott --json tv s             # машинный вывод
ott --timeout 60 tv p
```

Поиск каналов, программ, провайдеров и псевдонимов не учитывает регистр, в том
числе кириллицы. Точное название канала имеет приоритет. Если найдено несколько
подходящих каналов, CLI выводит варианты и ничего не переключает; выберите номер.
Номера `s`/`play` относятся ко всему каталогу провайдера, независимо от открытой
категории. `random` сохраняет старую семантику текущего списка воспроизведения.

`p` включает только программы, для которых `start <= сейчас < end` и есть
название. Каналы без текущего EPG пропускаются. Данные берутся у выбранного плеера;
незагруженное EPG запрашивается через его штатный сервис. Сбор ограничен 25 секундами:
при незавершённой загрузке CLI явно сообщает, сколько каналов проверено, и завершает
работу с кодом 3. Повторный запрос использует уже прогретый кеш. Если провайдер
поменялся во время запроса, результат отклоняется.
Код 3 сохраняется и с `--json`; JSON остаётся в stdout, предупреждение идёт в stderr.

## Данные провайдера

Файл для `provider-config` содержит `provider` и `settings`. Сначала выберите
нужного провайдера командой `provider`. Переданные поля обновляются, остальные
сохраняются. Данные не выводятся обратно в статусе/списке провайдеров/подтверждении.
Сохраняйте файлы с правами 600; используйте HTTPS вне доверенной локальной сети.

Xtream:

```json
{"provider":"xtream","settings":{"server":"https://provider.example","username":"YOUR_LOGIN","password":"YOUR_PASSWORD"}}
```

Stalker:

```json
{"provider":"stalker","settings":{"server":"https://provider.example/stalker_portal/c/","mac":"00:1A:79:00:00:01"}}
```

M3U:

```json
{"provider":"m3u","settings":{"playlist":"https://provider.example/list.m3u"}}
```

OTTClub:

```json
{"provider":"ottclub","settings":{"server":"provider.example","key":"YOUR_KEY"}}
```

У OTTClub поле `server` содержит только имя хоста с необязательным портом,
без `http://`, `https://`, пути или query. Протокол добавляет сам драйвер.

Используются штатные драйверы сохранения и перезагрузки. Родительская блокировка
настроек и ограничения платформы сохраняются; сначала разблокируйте настройки на
самом плеере. Другие провайдеры пока настраиваются через их интерфейс.

## Подтверждения и ограничения

CLI требует сервер и плеер с расширением request_protocol=1. Старые версии
продолжают поддерживать прежние команды, но не отвечают на запросы CLI.
`ok` означает ответ обработчика плеера, а `dispatched` — вызов штатного действия;
это не подтверждение появления видео, принятия PIN или фактической громкости ТВ.
`v` показывает то, что сообщает API платформы. Закрытие приложения может произойти
раньше отправки ответа на `exit`.

Команды и ответы хранятся в памяти с ограничениями размера и срока жизни. Повтор
потерянного ответа в одной сессии не выполняет относительную громкость второй раз;
после перезапуска плеера история не сохраняется. При таймауте не повторяйте
изменения вслепую: запрос может выполниться до окончания TTL (по умолчанию 60 с).
Отсчёт `--timeout` начинается до постановки в очередь. Ожидание HTTP ограничено
оставшимся временем, включая медленную передачу ответа; поздний ответ не считается
успехом. Таймаут прекращает ожидание CLI, но не отменяет уже отправленную команду.
Временные сетевые ошибки и HTTP 502/503/504 при чтении ответа повторяют только
чтение того же ID в оставшееся время. Постановка команды в очередь автоматически
не повторяется, даже если подтверждение её приёма потерялось.

Проверки: `go test -race ./...`, `python3 -m unittest discover -s tests`.
Сквозной тест в репозитории плеера:

```sh
OTT_CONTROL_BINARY=/path/to/ottplay-control-server \
OTT_CLI=/path/to/cli/ott.py node scripts/smoke-remote-cli.cjs
```
