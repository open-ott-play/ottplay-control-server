สำหรับ **k8a/fire8 และตัวเล่น Capacitor อื่น** ให้ใช้ตัวอัปเดต Wi-Fi ของตัวเล่นปกติ ไม่ใช่คำสั่งของเอเจนต์ root:

```sh
ott k8a update --variant api22
ott k8a update --version v1.1.58-beta.3 --variant api22
ott k8a update --variant api22 --prepare-only
ott k8a update status
```

หากไม่ระบุ `--version` จะเลือกเบต้าล่าสุดที่เผยแพร่ ใช้ `full` แทน `api22` บน Android 7+ CLI ค้นหารุ่นทางการ ตรวจแมนิเฟสต์ เตรียม APK และสอบถามสถานะก่อนขอติดตั้งหนึ่งครั้ง Android อาจขอการยืนยันบนแท็บเล็ต ปิด kiosk และปลดล็อกการตั้งค่าที่ป้องกันไว้อย่างชัดเจนก่อนบำรุงรักษา คำสั่งจะไม่เปลี่ยนนโยบายเหล่านี้ ดู[ขั้นตอน CLI ฉบับเต็ม](cli.md#capacitor-apk-updates-over-wi-fi)

ต้องมี APK ที่รองรับ `AppUpdate` ติดตั้งอยู่แล้ว มี Wi-Fi และตัวเล่นกำลังทำงานเชื่อมต่อคอนโทรลเลอร์ การอัปเดตปกติครั้งถัดไปไม่ต้องใช้ USB แต่เข้าถึงแท็บเล็ตออฟไลน์หรือ WebView ที่หยุดแล้วไม่ได้ การติดตั้งครั้งแรก ตัวอัปเดตใช้ไม่ได้ แอปเสีย หรือเครือข่ายขาด ยังอาจต้องกู้คืนที่เครื่อง นี่ไม่ได้หมายความว่ามีตัวตั้งเวลารุ่นอัตโนมัติหรือตัวติดตั้งเงียบทั่วไป

ส่วนที่เหลืออธิบาย**เอเจนต์บำรุงรักษา a1 ที่มี root อีกตัวหนึ่ง** ซึ่งจำกัดเฉพาะการติดตั้ง Matricom/API19 `play.ott.kitkat` ที่เตรียมไว้ ไม่ได้ติดตั้งหรือใช้งานได้อยู่แล้วบนอุปกรณ์ Fire/Capacitor ทั่วไป

หลังเตรียมระบบครั้งแรกด้วย USB และ root เอเจนต์ Android อิสระรับอัปเดตที่ลงลายเซ็นผ่านการเชื่อมต่อ HTTPS ขาออกของตนได้ ไม่ต้องมี WebView ที่ทำงานเพื่ออัปเดตตัวเอง เอเจนต์ 0.1.2 ยังรองรับชุด APK และตัวช่วยสัมผัสของระบบที่ประสานกัน พร้อมไฟล์กู้คืนที่บันทึกไว้และการตรวจสอบก่อนยืนยันถาวร

คู่มือนี้อธิบายเส้นทางทั้งหมด สำหรับฟิลด์แมนิเฟสต์ ขอบเขต และความต้องการฮาร์ดแวร์ที่แน่นอน โปรดดู[เอกสารเอเจนต์เนทีฟ](../native/android-agent/README.md#signed-updates-over-wi-fi)

## สิ่งที่อัปเดต

![สถาปัตยกรรม OTA: ไบต์รุ่นที่ผ่านการตรวจทานถูกลงลายเซ็น เผยแพร่ผ่าน HTTPS โดยตรง ตรวจโดยเอเจนต์อิสระ และตรวจหลังติดตั้ง การเผยแพร่เว็บแยกต่างหาก](images/ota-architecture.svg)

- **เอเจนต์เนทีฟ:** `kind: agent` แทนที่ไบนารี ARMv7 ของตนเอง วิธีนี้ยังใช้ได้เมื่อปิด OTT และใช้แอป HOME อื่น
- **เฉพาะ APK:** `kind: apk` แทนที่ตัวครอบโดยคงข้อมูลไว้ OTT ต้องเปิดและอยู่เบื้องหน้า ตัวช่วยฝังในรุ่นที่เตรียมต้องตรงกับตัวช่วยระบบที่ติดตั้งทุกประการ
- **APK และตัวช่วยสัมผัส:** `kind: bundle` อัปเดตทั้งสองส่วนเป็นคู่ เอเจนต์เก่าต้องรับการอัปเดตเฉพาะเอเจนต์ที่รองรับ bundle ก่อน
- **ตัวเล่นบนโฮสต์:** เผยแพร่อาร์ติแฟกต์เว็บที่ตรวจแล้วที่ origin เดิม จากนั้นโหลดใหม่และตรวจตัวเล่นที่ทำงาน การอัปเดต APK ไม่เผยแพร่ JavaScript บนโฮสต์ ดู[ขั้นตอนออกรุ่น](release-workflow.md)
- **คอนโทรลเลอร์และ CLI:** เผยแพร่คอนโทรลเลอร์และติดตั้งชุดโมดูล CLI ทั้งหมดแยกต่างหาก การอัปเดตอย่างใดอย่างหนึ่งไม่แทนที่โค้ดบนแท็บเล็ต

เฟิร์มแวร์ เคอร์เนล WebView ระบบ ตัวกลาง root และสคริปต์เริ่มต้นอยู่นอกฟอร์แมต OTA นี้ [เอกสารเนทีฟ](../native/android-agent/README.md#bootstrap) อธิบายขอบเขตการเตรียมระบบและกู้คืน การทำงาน OTA ที่รองรับไม่ต้องใช้ ADB ผ่านเครือข่ายหรือเชลล์ระยะไกลแบบอิสระ

## จากรุ่นที่ตรวจทานแล้วสู่การติดตั้งที่ยืนยัน

1. **เลือกไบต์ที่ตรวจแล้ว** เมิร์จการเปลี่ยนแปลงที่ตรวจทานหลัง CI ผ่าน ดาวน์โหลดอาร์ติแฟกต์รุ่นที่ต้องการแล้วตรวจรีวิชันซอร์ส หลักฐานรุ่นที่เปลี่ยนไม่ได้ และเช็กซัม ดึงไบนารี `agent` จากไฟล์เก็บเนทีฟ ตัวไฟล์เก็บเองไม่ใช่ payload เอเจนต์ที่ติดตั้งได้
2. **เตรียมและลงลายเซ็น** ใช้กุญแจส่วนตัว Ed25519 เดิมที่ตรึงกุญแจสาธารณะไว้ตอนเตรียมระบบ เก็บกุญแจและข้อมูลรับรองอุปกรณ์เป็นส่วนตัว
3. **เผยแพร่และตรวจการส่งข้อมูล** เผยแพร่เฉพาะ payload และ `signed.json` บนพาธ HTTPS ที่เปลี่ยนไม่ได้ ทั้งคู่ต้องส่งไบต์โดยตรงด้วย HTTP 200 ตัวอัปเดตปฏิเสธการเปลี่ยนเส้นทาง รัน `verify` ของเครื่องมือแพ็ก
4. **ส่งอัปเดตหนึ่งครั้ง** บันทึก ID คำขอและตรวจสถานะหลังรับการยืนยัน คำตอบสูญหายหรือไม่แน่นอนไม่ใช่เหตุให้ทำซ้ำโดยไม่ตรวจ
5. **ยืนยันผล** เปรียบเทียบแฮชและรุ่นที่ติดตั้งซึ่งอ่านใหม่กับรุ่นที่เตรียม สำหรับตัวเล่นที่ทำงาน ให้ตรวจเป้าหมาย kiosk คิว และการเล่นที่เดินหน้าด้วย ภาพและเสียงจริงต้องสังเกต

ตัวอย่างรุ่นเอเจนต์ ให้แทนรุ่นที่เลือกและพาธจริง:

```sh
python3 native/android-agent/prepare_update.py prepare \
  --kind agent --version 0.1.2-beta.4 \
  --payload /private/release/agent \
  --url https://updates.example/0.1.2-beta.4/agent \
  --manifest-url https://updates.example/0.1.2-beta.4/signed.json \
  --key /private/update.key --output /private/ota-0.1.2-beta.4

# Publish the prepared agent and signed.json, then verify the published bytes.
python3 native/android-agent/prepare_update.py verify \
  --directory /private/ota-0.1.2-beta.4

ott --receipt --timeout 40 a1 android update \
  https://updates.example/0.1.2-beta.4/signed.json ENVELOPE_SHA256
ott --timeout 30 a1 android status
ott a1 android operation REQUEST_ID
```

`ENVELOPE_SHA256` คือ `envelope_sha256` ของเครื่องมือแพ็ก ไม่ใช่แฮช payload ส่วน `accepted` หมายถึงรับคำขอ ไม่ได้หมายถึงติดตั้งสำเร็จ การแทนที่ตัวเองอาจทำให้ใบรับการทำงานเก่าเป็น `unknown` รันไทม์ใหม่ รุ่นเอเจนต์ที่คาด และแฮชติดตั้งที่ตรงกันเป็นหลักฐานติดตั้ง [เอกสาร CLI](cli.md#independent-android-agent) อธิบายการส่งต่อเนทีฟอิสระและการจัดการใบรับ

## การกู้คืนธุรกรรม APK/ตัวช่วย

![ธุรกรรม APK/ตัวช่วย: ตรวจล่วงหน้า เก็บคู่เดิม ใช้ ตรวจ ยืนยัน หากล้มเหลวคืนคู่เดิม และกู้คืนไม่จบยังบล็อกการเปลี่ยนแอป](images/ota-transaction.svg)

ชุดมีเพียง `app.apk` และ `ott-touch-guard` เครื่องมือแพ็กสร้างโดยตรงจาก wrapper APK ที่ลงลายเซ็นได้ด้วย `--kind bundle --apk` มันดึงตัวช่วยฝังไว้ จึงทำให้สองสำเนาที่ส่งตรงกัน ดู[คำสั่ง bundle และข้อกำหนด](../native/android-agent/README.md#coordinated-wrapper-and-helper-updates)

ก่อนเปลี่ยนไฟล์ เอเจนต์ต้องมีคู่ที่ติดตั้งตรงกัน พื้นที่ว่างพอ ตัวเล่น OTT เบื้องหน้าที่ตอบสนอง พาร์ทิชันระบบอ่านอย่างเดียว และการประกาศรองรับดาวน์เกรด APK สำหรับ kiosk ที่ล็อก จะตรวจ ID ช่อง TV เดิมหรือ ID VPortal ตามลำดับ แค่คิวยาวเท่ากันไม่พอ คิวล็อกที่ไม่รองรับถูกปฏิเสธ แอป OTT ที่ตั้งใจปิดก็ถูกปฏิเสธเพื่อรักษาแอป HOME ปัจจุบันของผู้ใช้

ไฟล์กู้คืนและธุรกรรมรอถูกเก็บถาวรก่อนหยุดแอป เอเจนต์รอแอปและตัวช่วยเก่าหยุด แทนที่ตัวช่วยแบบอะตอม คืน `/system` เป็นอ่านอย่างเดียว ติดตั้ง APK แล้วตรวจผล หากใช้หรือยืนยันล้มเหลวจะคืนคู่เดิม การกู้คืนเมื่อเริ่มระบบคืนไฟล์โดยไม่เปิด OTT หรือยึด HOME

หากกู้คืนไม่จบ `updates.recovery_failed` เป็นจริง การวินิจฉัยและซ่อมเฉพาะเอเจนต์แบบลงลายเซ็นยังใช้ได้ แต่การเปลี่ยนแอปและ watchdog การเล่นถูกบล็อก ห้ามลบธุรกรรมที่บันทึกเพื่อบังคับติดตั้ง การกู้ไบนารีไม่ย้อนการย้ายข้อมูลแอป และเฟิร์มแวร์ยังอาจปฏิเสธการดาวน์เกรด ดู[ข้อจำกัดการกู้คืน](../native/android-agent/README.md#coordinated-wrapper-and-helper-updates)

## ผลลัพธ์และบันทึกการยอมรับ

![กราฟตรวจสอบ: ทดสอบ CLI 488 รายการ เครื่องมือออกรุ่น 576 รายการ และแพ็ก OTA 6 รายการ แท็บเล็ตอ้างอิงใช้เอเจนต์ใหม่ที่ตรวจแล้ว แต่การยอมรับ APK/ตัวช่วยบนเครื่องจริงยังรอ](images/ota-validation.svg)

การตรวจการใช้งานวันที่ 14 ตุลาคม 2026 ผ่านการทดสอบ CLI 488 รายการ (ข้ามหนึ่งรายการ) เครื่องมือออกรุ่น 576 รายการ แพ็ก OTA หกรายการ การตรวจ Go เนทีฟด้าน race/static และบิลด์ ARMv7 จำนวนเหล่านี้บอกขนาดชุดทดสอบ ไม่ใช่ความครอบคลุมหรือประสิทธิภาพ การทดสอบแทรกข้อผิดพลาดลองไฟล์เก็บไม่ถูกต้อง ธุรกรรมขาดตอน การคืนค่าบางส่วน การเปลี่ยนเป้าหมาย และการบล็อกระหว่างกู้คืน การตรวจทานอิสระยังพบและแก้การตรวจตัวตนคิวไม่เพียงพอ และการตรวจ APK/ตัวช่วยไม่ตรงกันระหว่างโฮสต์กับอุปกรณ์

สถานะที่ตรวจวันที่ 15 ตุลาคม 2026:

- การใช้งาน OTA เมิร์จใน [PR คอนโทรลเลอร์ #104](https://github.com/open-ott-play/ottplay-control-server/pull/104) และรวมใน [v0.1.2-beta.4](https://github.com/open-ott-play/ottplay-control-server/releases/tag/v0.1.2-beta.4) แล้ว
- แพ็กเอเจนต์ลงลายเซ็นปัจจุบันและก่อนหน้าเผยแพร่ที่[โฮสต์ส่ง OTA](https://android-updates.ottplay.here.now/) ไบต์ payload และซองข้อมูลถูกดาวน์โหลดและเปรียบเทียบสำเร็จผ่าน HTTPS โดยตรง
- แท็บเล็ตอ้างอิงอัปเดตจาก `0.1.1-beta.21` เป็น `0.1.2-beta.4` ผ่านช่อง OTA อิสระ รุ่นเอเจนต์ที่ทำงานและ SHA-256 ที่ติดตั้งตรงกับรุ่นที่เลือก รันไทม์เปลี่ยนแต่ ID บูต OS เดิม OTT ยังไม่มีกระบวนการแอปทำงาน และไม่มีการส่งคำสั่งเปิดแอปหรือเลือก HOME
- สถานะเนทีฟรายงานแฮชตัวช่วยสัมผัสระบบ ไม่มี bundle รอ และไม่มีกู้คืนล้มเหลว เมทาดาทา APK ใช้ไม่ได้ ดังนั้นข้อสังเกตนี้ไม่ได้ยืนยันรุ่นหรือแฮช APK ที่ติดตั้ง
- ธุรกรรม APK/ตัวช่วยที่ประสานกันผ่านการตรวจฝั่งโฮสต์แล้ว แต่การติดตั้งจริง กู้คืนดาวน์เกรด ภาพและเสียงยังไม่ได้รับการยอมรับบนแท็บเล็ตอ้างอิง

ทุกการปล่อยครั้งถัดไป ให้เก็บซอร์ส/เช็กซัมรุ่น แฮชซองข้อมูลที่เตรียม ID คำขอ สถานะเนทีฟก่อน/หลัง และผลยอมรับบนเครื่องจริงแยกต่างหาก การดาวน์โหลดสำเร็จหรือใบรับคำสั่งแทนข้อสังเกตเหล่านี้ไม่ได้
