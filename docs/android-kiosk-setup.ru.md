# Android-планшет: строгий киоск Plex и автозапуск

[English](android-kiosk-setup.md) · [ADB](android-adb.md) ·
[OTT Home](../native/android-home/README.md) · [USB-менеджер](android-usb-manager.ru.md)

Для выделенного планшета отдельно настраиваются очередь, строгий киоск OTT и
автозапуск Android. Установка APK и успешное пробуждение экрана ещё не доказывают,
что приложение откроется после полной перезагрузки.

## Установка и идентичность

1. Зафиксируйте физический планшет, alias/UUID OTT, alias USB-менеджера, серийный
   номер, модель, Android ID и SDK. Имена OTT и USB могут отличаться. Не копируйте
   токен другого устройства и не определяйте планшет только по имени.
2. Выберите официальный APK для его SDK, проверьте SHA-256 релиза, пакет и подпись.
   Устанавливайте через `install -r`, сохраняя данные. Если USB уже обслуживается
   общим менеджером, используйте его транзакции: второй ADB-сервер не запускайте.
3. Подключите плеер к серверу управления с собственными реквизитами, проверьте
   `ott TABLET`, загрузите нужный пресет и выполните
   `ott TABLET load PRESET verify`. Домашний профиль и localhost-профиль для
   разработки на Mac не взаимозаменяемы.

## Проверка Plex с самого планшета

```sh
ott TABLET plex libraries
ott TABLET plex library --preview 'НАЗВАНИЕ БИБЛИОТЕКИ'
```

Сверьте ID, название и число записей. Доступ с Mac не подтверждает доступ с
планшета: отдельно проверяйте адрес, маршрутизацию, TLS и реквизиты. Предпочитайте
HTTPS с действительным сертификатом. Если старой прошивке необходим HTTP внутри
частной LAN, меняйте только этот плеер и явно фиксируйте, что токен и видео идут
по LAN без шифрования. Не переписывайте общий пресет и не отключайте проверку
сертификатов глобально. Не публикуйте токены и частные ссылки на видео.

Смена адреса Plex сбрасывает выбранные корни библиотек. Выберите провайдера
**Plex**, откройте **Plex settings → Folders**, отметьте строку нужной библиотеки
(а не только **Browse folders**), нажмите **Ok**, затем **Save and open library**.
В `1.1.58-beta.19` одних реквизитов сервера
недостаточно: может открыться выбор папок, пока `ready` остаётся `false`.
Завершите выбор папки до запуска очереди. Не подменяйте провайдера на M3U ради
`ready: true`: видео Plex так запустится, но `kiosk on --strict` может сохранить
ожидающую M3U-политику без привязанного видео. Она не блокирует и не
восстанавливает очередь Plex.

## Очередь и строгий киоск

```sh
ott TABLET kiosk off
ott TABLET plex shuffle 'НАЗВАНИЕ БИБЛИОТЕКИ'
ott TABLET plex status
ott TABLET debug --engine
# Продолжайте только после запуска нужной очереди.
ott TABLET kiosk on --strict
ott TABLET plex status
ott TABLET kiosk status
ott TABLET debug --engine
```

Для исходного порядка используйте `plex library` вместо `plex shuffle`. Shuffle
выбирает случайный порядок один раз; киоск повторяет его. Проверьте состав
очереди, `enabled: true`, `strict: true` и привязку политики к очереди Plex.
Политика `waiting` без канала или видео не подтверждает работающий киоск.
Проверьте изображение и рост позиции/счётчика
кадров в двух замерах. Ответ команды и надпись `playing` недостаточны.
Проверьте естественный переход после окончания ролика. Если полный цикл не
проверялся, укажите это явно.

Строгий киоск ограничивает интерфейс плеера, но не означает Android device owner
или блокировку Home, Recents, уведомлений и Settings. Сохраняйте системный
лаунчер и способ обслуживания.

## Автозапуск

Соберите и проверьте [OTT Home 0.2.0](../native/android-home/README.md), сохранив
существующий ключ подписи. Установите `play.ott.home` рядом с `play.ott.foss`.
Откройте `play.ott.home/.StartupActivity` и включите **Start OTT after reboot**.
По умолчанию переключатель выключен. Это не меняет официальный APK плеера,
подпись его обновлений, профили и назначение кнопки Home.

Если прошивка предоставляет выбор Home, дополнительно выберите
**OTT Home → Always**. На старых Fire без такого выбора переключатель включает
независимый запуск после загрузки. Ранее выбранный default Home продолжает
работать; для полного отката отключите оба механизма.

`recover_on_boot` общего USB-менеджера — отдельный механизм. Ему нужны NAS и
USB-кабель; он обрабатывает новую загрузку, а не постоянно перезапускает упавшее
приложение. При проверке автономного запуска оставьте эту настройку выключенной,
чтобы USB-восстановление не скрывало проблему. Защищённый экран блокировки
разблокируйте обычным способом.

## Приёмка и передача

Храните доказательства приватно, без секретов в публичных отчётах:

- Версии/хеши APK, соответствие физического устройства именам OTT/USB и пресет.
- Библиотека, число записей, порядок, строгий киоск и начальное движение видео.
- Разные boot ID до/после настоящей перезагрузки и `sys.boot_completed=1`.
- Отсутствие ручного запуска OTT и USB-восстановления между reboot и проверкой.
- OTT на переднем плане, восстановление связи, очереди, strict и движение видео.
  Результат `requested` в OTT Startup означает только отправленный запуск.
- Отдельно: кнопка питания гасит экран и звук, обычная разблокировка возобновляет.
- Ограничения: необходимость разблокировки, помощь USB, непроверенные физические
  выходы, ошибки потоков или нехватка памяти. Не выдавайте их за полную приёмку.

Для следующего планшета повторите проверки, не копируя вывод о предыдущем.
На старых Fire M3U может требовать `hls.js` из-за сбоя штатного HLS; это не
гарантирует устойчивость Plex.

## Обслуживание и откат

Снимите киоск командой `ott TABLET kiosk off`. В **OTT Startup** выключите
**Start OTT after reboot**, затем верните прежний Home, если меняли его. При
необходимости удалите только `play.ott.home` через проверенный USB-транспорт;
данные `play.ott.foss` сохраняйте. Отключение автозапуска само по себе не снимает
киоск и не меняет очередь.
