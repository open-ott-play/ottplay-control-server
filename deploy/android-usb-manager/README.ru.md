В каталоге находятся шаблоны развёртывания и
[`Dockerfile`](Dockerfile) контейнера общего менеджера.
Сам Python-менеджер работает на USB-хосте. Образ предоставляет ADB, Python
и инструменты для неделимых операций обслуживания, но не содержит второго
реестра устройств или службы восстановления. Подготовка устройств, команды,
миграция, ограничения восстановления и откат описаны в
[руководстве оператора](../../docs/android-usb-manager.ru.md).

Для установки без Git скачайте `ottplay-control-server-deployment.tar.gz`
и `release-manifest.json` из одного
[релиза](https://github.com/open-ott-play/ottplay-control-server/releases).
Сверьте хеш архива и распакуйте его в новый каталог по разделу
[«Получение пакета развёртывания»](../../docs/android-usb-manager.ru.md#получение-пакета-развёртывания).
Пакет содержит этот рецепт и шесть скриптов хоста и удалённых команд в `tools/`;
сохраните структуру каталогов. В прежних пакетах, включая `v0.1.5-beta.6`,
этих скриптов нет: вместо них нужен архив исходников того же тега.
Готового образа USB-транспорта в пакете нет. OCI-образ сервера управления
из релиза предназначен для другой задачи.

## Происхождение исходников и образа

База — `python:3.12.14-slim-trixie`, закреплённая по
`sha256:44ff437bba879d4941b710a369a8f19266aea34b29002807f0c487fabc9eec9b`.
Базовый образ, инструкция APT и установка `websocket-client==1.9.0`
с проверкой хеша рассмотрены в
[PR 128, ревизия b4181bf](https://github.com/open-ott-play/ottplay-control-server/tree/b4181bff35faff9a27c9bc1e86b0004c43ad1efc/deploy/android-manager).
Текст этих инструкций сохранён для повторного использования готового кеша
сборки. Необязательный пакет WebSocket нужен существующим универсальным
клиентам обслуживания; перенесённые адаптеры CDP могут использовать только
стандартную библиотеку Python.

Этот рецепт удаляет установленный `pip` после установки закреплённого wheel,
не включает менеджер и восстановление из PR 128, запускает ADB основным
процессом и отключает унаследованные health checks. Удаление установщика
сокращает доступный код, но само по себе не доказывает отсутствие уязвимостей.

Проверенный образ PR 128 имел ID
`sha256:f2ed00bac5b137c1a4bd18db8f7675677e7c36d4444618eec8f996e205531a6a`.
У него другая точка входа и несовместимая проверка heartbeat.
Это справочный артефакт, а не сборка данного Dockerfile.
Не приписывайте этому рецепту его ID, происхождение или результаты сканирования.

Репозитории APT не закреплены на снимке. Поэтому новая чистая сборка может
получить более свежие системные пакеты при неизменных digest базы и хеше
Python wheel. Для принимаемой сборки сохраняйте ревизию исходников,
сборщик и платформу, итоговый ID, версии пакетов и результат сканирования.
В рабочей конфигурации указывайте проверенный неизменяемый ID или digest.

## Сборка без нагрузки на занятый USB-хост

Предпочтительно собирать и сканировать на отдельной машине.
Целевому хосту нужен готовый проверенный образ, а не загрузка пакетов
или среда сборки.

При использовании подготовленного локального сборщика сначала убедитесь,
что точная база доступна локально, а слои APT и установки wheel есть в кеше.
Загрузка только итогового образа PR 128 не гарантирует ни того, ни другого.
Из корня репозитория или распакованного пакета можно выполнить попытку
с отключённой сетью шагов:

```sh
docker image inspect python:3.12.14-slim-trixie@sha256:44ff437bba879d4941b710a369a8f19266aea34b29002807f0c487fabc9eec9b
docker build --pull=false --network=none \
  --tag ott-android-transport:review \
  deploy/android-usb-manager
docker image inspect ott-android-transport:review
```

`--network=none` действует на шаги сборки, но не обещает, что сборщик никогда
не обратится к registry при поиске базового образа. До запуска на ограниченном
хосте проверьте, что его сборщик использует именно локальную базу.
Если слоя APT или wheel нет, остановите попытку; не разрешайте незаметно
полноценную сетевую пересборку на USB-хосте.

BuildKit учитывает сетевой режим шага в ключе кэша. Поэтому кэш,
созданный с обычной сетью, может не подойти для попытки выше.
Повторно используйте его только после проверки точной базы и цепочки
инструкций; остановите сборку, если любой шаг установки пакетов начал
выполняться вместо отметки `CACHED`. Последнее удаление `pip` явно
использует `RUN --network=none` и не требует сети, даже если предыдущие
кэшированные шаги сохраняют исходный сетевой режим.

Перед изменением рабочей конфигурации проверьте версии Python и ADB,
просканируйте точный итоговый образ, проверьте бинарную передачу файлов
и подготовку APK. Затем выполните приёмку идентичности устройств,
авторизации ключей, сна и загрузки по основному руководству.
Совместимость ADB 34 с KitKat и Fire нужно подтвердить на устройствах;
номер версии сам по себе её не доказывает. Сохраняйте текущий образ
и закрытую резервную копию до завершения периода возможного отката.

## Лимиты при работе

Менеджер на хосте, а не Dockerfile, задаёт 256 МиБ памяти,
256 МиБ суммарно памяти и swap и CPU shares 128 без жёстких квот CPU и PID.
Он применяет `--no-healthcheck`, `--network none`, корневую файловую систему
только для чтения, сбрасывает capabilities и передаёт только точные USB-узлы.
Ограниченный tmpfs `/tmp` расходует тот же бюджет памяти.
Адаптер подготовки пишет блоками по 1 МиБ и принимает до 128 МиБ за операцию;
операции используют общую блокировку менеджера.

В документации Docker описаны
[лимиты памяти, swap и CPU shares](https://docs.docker.com/engine/containers/resource_constraints/)
и [параметр `--no-healthcheck`](https://docs.docker.com/reference/cli/docker/container/run/#no-healthcheck).
